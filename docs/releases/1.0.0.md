## What's new since v0.1.0

- An adaptive application workspace with task navigation, system/light/dark
  themes, retained forms and a canvas that fits its available space.
- Actual unsaved widget previews, guided incoming triggers, ordinary money and
  quantity conditions, donation tiers, and first/all matching alert sets.
- Advanced arrangement: grouping, alignment, distribution, ordering, locking,
  hiding, transforms, touch controls and numeric/button alternatives.
- Event List, goal/progress widgets and additional built-in media tools.
- Custom widgets with a local code editor, typed settings, explicit permissions,
  an isolated worker sandbox and separate preview/live storage.
- Portable overlay/widget packages, fresh import identities, disabled import
  permissions and reference remapping. Legacy-compatible designs use format v1;
  conditional designs and alert sets use v2. Older applications reject v2.
- Limited opt-in local StreamElements compatibility and migration, replay,
  sample, backup, sanitization and diagnostic utilities.
- An illustrated 20-chapter offline guide with 12 owned examples, updated wiki
  navigation, installation instructions and recovery guidance.
- DOMPurify updated to 3.4.16 for GHSA-p98j-92pf-mc4p, including Monaco's
  embedded sanitizer in the shipped code editor.

Existing chat, supporter accounting, automation, integrations, revision recovery,
backup/restore, permissions and HTTP/LAN workflows remain available. Existing OBS
addresses continue to work. Alert sets select eligibility before playback queues;
cooldown/overflow does not choose a different fallback design.

## Downloads and upgrading

The build produces `TDSBLive-1.0.0-win-x64.zip`,
`TDSBLive-1.0.0-win-x64-setup.exe` and `SHA256SUMS.txt`. Both application packages
include the runtime, offline guide and supplied Streamer.bot import.

Make a backup and quit the old application before updating. Install the new
version or extract the complete ZIP into a separate folder. Application data
normally remains in `%LOCALAPPDATA%\TDSBLive`, separate from program files.
Check your saved connections and OBS sources before broadcasting. See
[updating](../user-guide/Install-and-Update.md) and
[backup/recovery](../user-guide/Backup-and-Recovery.md).

## Qualification and boundaries

The full protected pipeline runs frontend/Core/Host regressions, generated
contract checks, real-browser legacy/redesign/synthetic scenarios, native
portable/installed restart/restore/install/startup/uninstall, package version
verification, offline-guide checks, SonarQube and CodeQL. A build is qualified
only after its exact-source checks pass; the release-preparation PR records those
results. Existing goal records are retained in the
[implementation plan](../implementation-plan.md) and
[UI completion audit](../ui-redesign-completion-audit.md).

UI delivery uses the operator-approved synthetic acceptance. It does not claim
observed human usability, screen-reader speech, physical touch or hearing.
Actual paid-platform delivery and native streaming-PC performance remain
unqualified. Linux uses the Windows application through a compatibility runner;
Wine/Proton behavior and performance vary. VTube Studio-specific work remains
deferred, and the local StreamElements bridge does not supply cloud services.

Preview tests remain isolated from live events, financial writes and automation;
preview audio requires opt-in. Custom permissions remain explicit. HTTP works
without certificates; optional authenticated LAN access is off by default and
HTTP does not encrypt traffic.
