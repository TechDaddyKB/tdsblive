# TDSBLive 1.0.1

This cumulative release includes every merged application change since v0.1.0.
There is no separate published v1.0.0 download. Use 1.0.1 for the current editor,
alerts and desktop controls.

## Download

Expand **Assets** below and choose one application download:

- **Windows installer:** `TDSBLive-1.0.1-win-x64-setup.exe`.
- **Windows folder version:** `TDSBLive-1.0.1-win-x64.zip`. Extract everything,
  then open `TDSBLive.exe`.
- **Linux launcher with Windows backend:** `TDSBLive-1.0.1-linux-x64-wine.tar.gz`.
  Extract everything, then open `TDSBLive`. Install Wine or UMU/Proton first.
  This download supports both runners; the backend still uses Windows compatibility.
- **Download checksums:** `SHA256SUMS.txt` covers all three application files.

The application downloads include their .NET runtime, offline guide and supplied
Streamer.bot import. **Source code** archives are for developers. Start-at-login
is optional and off by default; the Linux shortcut does not enable it.

## What's new

- A blue **T** tray icon on Windows and a native Linux tray. Choose **Open editor**,
  **Restart** or **Quit**. Restart and Quit ask first, with **Cancel** selected.
- Linux first-run setup helps choose installed Wine or UMU, the existing settings
  folder and saved setup. Repeated launches open the existing editor. A crashed
  backend is not automatically restarted; explicit recovery retains your setup.
- A focused, adaptive editor with task navigation, light/dark/system themes,
  fitted canvas, actual draft previews and accessible arrangement alternatives.
- Friendly incoming trigger choices, money/quantity conditions, donation tiers,
  and ordered alert sets that choose the first or all matching designs.
- Advanced grouping, alignment, distribution, transforms, layers, locking and
  hiding, plus Event List, goals/progress and additional media widgets.
- Custom widgets with a local code editor, typed settings, explicit permissions,
  sandboxed workers and separate preview/live storage.
- Portable overlay/widget packages with new import identities and disabled
  imported permissions. Conditional designs use format v2; older apps reject it.
- Limited optional local StreamElements compatibility and migration tools.
- An illustrated 21-chapter guide in the application and updated online wiki.
- DOMPurify 3.4.16 addresses GHSA-p98j-92pf-mc4p, including Monaco's sanitizer.
- Repairs for native Linux new-prefix creation, duplicate ownership, backend-crash
  recovery, retained Proton globalization and off-screen high-DPI setup windows.

Existing chat, finance, automation, integrations, permissions, revisions,
backup/restore and HTTP/LAN controls remain available. Existing OBS addresses
continue working. Preview tests remain isolated and preview audio requires opt-in.

## Update safely

1. Save your editor changes and download an application backup.
2. Quit TDSBLive and wait for it to stop. Closing the browser leaves it running.
3. Run the new Windows installer, or extract the complete download into a new folder.
4. On Linux, retain the same runner, prefix and saved setup. Leave **Start a new
   empty TDSBLive setup** unchecked when updating. Use `./TDSBLive --setup` in
   the new folder to select its included backend and update the optional shortcut.
5. Check your connections, one test event, OBS graphics and sound before a show.

Tray actions do not save unfinished forms. They do not close OBS or your bots.
Open `guide/Home.html` in the application folder for offline instructions, or use
the [user guide](https://github.com/TechDaddyKB/tdsblive/wiki).

## Accepted limitations

Linux native tray memory overhead and KDE panel-only disappearance remain open
for investigation. If the KDE panel vanishes without showing fallback controls,
use the editor's **Backup and recovery** controls to restart or quit.
Wine/Proton CPU and memory use vary; test the load on your streaming computer.
A fully native Linux backend and native-companion support for Bottles are deferred.

Representative isolated Windows/Linux desktop and local OBS tests do not qualify
every runner or computer. Native Windows streaming-PC/OBS performance, paid
Rumble Rant/Ko-fi/Twitch Bits delivery and physical human/touch/hearing checks
retain the existing evidence limits. VTube Studio-specific work stays deferred.
See [known issues](https://github.com/TechDaddyKB/tdsblive/blob/main/docs/known-issues.md)
and [release evidence](https://github.com/TechDaddyKB/tdsblive/blob/main/docs/tray-release-plan.md).

This is the last planned feature release for a while. Bug/security fixes and a
future fully native Linux backend remain possible.
